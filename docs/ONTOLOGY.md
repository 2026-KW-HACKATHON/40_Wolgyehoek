# 동네서랍 아이디어 시장 온톨로지

동네서랍은 지역 아이디어를 카드 한 장으로 끝내지 않고, **누가 · 어디서 · 누구를 위해 · 어떤 문제를 풀려다 · 어떻게 됐는지**를 잇는 지식 그래프로 쌓는다. 같은 문제를 몇 번, 어디서, 누가 시도했고 무엇에 막혔는지가 보이면 새 아이디어의 중복을 미리 알고, 빈틈과 시장성을 가늠할 수 있다.

구현: `backend/.../ideas/Ontology.java`(사전), `KnowledgeGraphService.java`(그래프·신호), `GET /api/ideas/graph`. 화면: 서랍의 3D 지식 그래프.

## 개체 (노드)

| 유형 | 뜻 | 만드는 방법 | 예 |
|---|---|---|---|
| `IDEA` 시도 | 제안·과제·사업 하나 | 동네서랍 카드, 공개 기록(`archive.json`) | 똑똑똑돌봄단 정기 안부 확인 |
| `NEED` 문제 영역 | 시도가 풀려는 니즈 | 개념 사전(`IdeaTaxonomy.CONCEPTS`) 키워드 | 어르신 돌봄, 장터·플리마켓 |
| `PLACE` 장소 | 시도가 벌어지는 구역 | 구역 사전(`IdeaTaxonomy.ZONES`) | 광운대 앞, 석계역, 월계1동 전역 |
| `ACTOR` 주체 | 제안·운영한 조직 | 공개 기록의 `by`, 동네서랍 주민·시연 팀 | 월계1동주민센터, 광운대 캠퍼스타운 |
| `BENEFICIARY` 대상 | 누구를 위한 시도인가 | 대상 사전(`Ontology.BENEFICIARIES`) 키워드 | 어르신, 청년·대학생, 상인 |
| `BARRIER` 장벽 | 멈춘 이유 | 결론의 사유 태그(보류·중단·정체만) | 운영 주체 없음, 예산·공간 부족 |
| `SOURCE` 출처 | 근거 문서 | 공개 기록의 출처 URL | 노원구의회 행정사무감사 |

개인 이름은 노드로 만들지 않는다. 동네서랍 주민 카드는 `동네서랍 주민` 한 주체로 묶는다.

## 관계 (엣지)

| 관계 | 방향 | 뜻 |
|---|---|---|
| `ADDRESSES` | IDEA → NEED | 이 문제 영역을 다룬다 (여러 개 가능) |
| `LOCATED_IN` | IDEA → PLACE | 이 구역에서 벌어진다 |
| `LED_BY` | IDEA → ACTOR | 이 주체가 제안·운영했다 |
| `SERVES` | IDEA → BENEFICIARY | 이 대상을 위한 시도다 |
| `BLOCKED_BY` | IDEA → BARRIER | 이 이유로 멈췄다 |
| `CITES` | IDEA → SOURCE | 이 문서가 근거다 |
| `CONTINUES` | IDEA → IDEA | 멈춘 시도를 이어받았다 |

## 결과 상태

`GOING`(시행·진행·성사) · `STOPPED`(보류·중단·정체) · `LIVE`(동네서랍에서 검증 중) · `UNKNOWN`(공개 기록에 결과 없음). 결과를 모르는 기록을 실패로 세지 않는다.

## 기회 신호 (문제 파악·시장성 검증)

그래프에서 자동으로 뽑는 신호다. 점수는 정렬용이며 시장 규모가 아니다.

| 신호 | 조건 | 쓰임 |
|---|---|---|
| `DEMAND` 수요 미충족 | 동네서랍 반응·함께해요가 있는데 시행된 시도가 없다 | 가장 먼저 검증할 문제 |
| `STALLED` 장벽 해결 | 같은 문제·구역에서 멈춘 시도가 있다 | 장벽(예: 운영 주체)을 해결하면 열리는 시장 |
| `SPREAD` 확산 | 한 구역에서 시행됐는데 다른 구역엔 시도가 없다 | 검증된 해법을 옮길 곳 |
| `UNVERIFIED` 결과 미확인 | 같은 문제·구역에서 2번 이상 나왔는데 결과가 남지 않았다 | 동네서랍으로 수요를 다시 검증할 대상 |
| `CROWDED` 포화 | 같은 문제·구역에서 3건 이상 시행 중 | 새로 하려면 차별점이 필요 |
| `WHITESPACE` 빈칸 | 사전에 있는 문제 영역인데 시도가 없다 | 아직 아무도 손대지 않은 영역 |

## 확장

- **데이터 수집:** 출처·주체 노드를 따라 다음 자료(같은 주체의 다른 사업, 같은 장소의 기사)를 찾고, LLM으로 개체를 뽑은 뒤 사람이 검수해 `archive.json`에 더한다.
- **시장성:** 서울시 상권분석 서비스의 업종·매출, 생활인구 같은 공공데이터를 `PLACE` 속성으로 붙이면 수요 신호를 정량화할 수 있다.
- **정책:** 예산·사업명·운영 기간을 `IDEA` 속성으로, 지원 사업(주민참여예산, 캠퍼스타운)을 `PROGRAM` 개체로 추가하면 어떤 제도를 거친 시도가 이어지는지 볼 수 있다.
- **표준:** 공공데이터로 내보낼 때는 개념·구역 사전을 SKOS, 그래프를 JSON-LD로 옮긴다. 수천 건 규모까지는 Postgres의 현재 구조로 충분하다.
