# 동네서랍 · 모바일 카드와 시연 크레딧 (2026-10-07)

현재 제품 방향의 정본이다. 이전 PRD의 단계형 수요 검증은 기존 기록 호환을 위해 남기되, 첫 화면의 참여 방식은 모바일 카드 스와이프로 교체한다.

## 의도와 화면

주민은 짧은 아이디어 카드를 한 장씩 읽고 생각을 남긴다. 팀은 크레딧으로 응답 모집 예산을 준비한다. 참여 보상은 가상의 동네 이용권으로 이어진다. 실제 지역 소비와 연결할 수 있는 구조를 시연하지만 결제·제휴·상권 효과가 검증됐다는 주장은 하지 않는다.

- 모든 경로는 하나의 모바일 화면이다. 넓은 모니터에서도 최대 480px이며 데스크톱 사이드바·별도 화면은 없다.
- 따뜻한 주황 `#b54b25`, 크림 표면, 장끼의 공용 Button/Input/Textarea 컴포넌트와 Pretendard를 유지한다.
- 발견: 오른쪽 = 관심, 왼쪽 = 패스. 실제 가로 드래그와 버튼·키보드 좌우 방향키를 제공한다. 세로 움직임은 읽기 스크롤이다.
- 스와이프 후 이유 선택 창이 열린다. 취소하면 저장하지 않는다. 이유 없이 10C, 공백 제외 10자 이상·전체 500자 이내 이유와 함께 30C. 양쪽 방향의 보상은 같다.
- 성공 시에만 카드가 넘어간다. 실패 시 내용이 유지되며 무보상으로 건너뛸 수 있다. 카드/기기당 보상은 한 번이고 이후 이유 추가·방향 변경으로 더 지급하지 않는다.
- 동네 혜택: 보상 잔액, 가상 매장 이용권, 교환 확인, 내 이용권·사용 확인 시연, 보상 거래 기록.
- 팀 공간: 별도 팀 예산 지갑, 시연 충전, 아이디어 등록, 예산 배정, 관심/패스·이유, 모집 마감·잔액 반환, 팀 거래 기록.
- 내 활동: 참여 기록, 결론·이어받기 소식과 닉네임. 왼쪽으로 반응한 기기도 결론·이어받기 소식을 받는다.

## 크레딧 보존과 권한

- `DEMO_CREDITS=true`에서만 발행·보상·교환이 가능하다. 기본값 false이며 실제 결제 공급자나 현금 충전은 없다.
- 팀 충전 500C / 1,000C는 **팀 예산 지갑**으로만 들어간다. 이용권은 **참여 보상 지갑**으로만 교환한다. 충전을 참여 실적처럼 사용할 수 없다.
- 팀만 자기 카드에 30~10,000C(10C 단위)를 배정한다. 배정 시 팀 지갑에서 캠페인 예산으로 옮긴다.
- 예산이 30C 이상인 진행 중 카드만 발견에 표시한다. 반응 10C 또는 30C를 지급할 때 실제 예산에서 차감한다. 마지막 30C보다 적으면 추가 배정까지 보상 참여가 중지된다.
- 자기 카드 보상, 숨긴 카드·종료 카드의 신규 참여, 부족한 예산·잔액, 잘못된 입력은 거부한다.
- 카드 행 잠금, 유일한 `(card_id,device_id)`와 트랜잭션으로 중복·동시 지급을 막는다. 지갑·예산·반응·원장은 함께 반영된다.
- 운영자가 숨긴 카드는 새 참여를 받지 않지만 팀 목록에서 소진되지 않은 예산을 반환할 수 있다. 운영자는 숨긴 카드 상세를 기존 권한으로 볼 수 있다.
- 모집 마감은 제안자만 한다. 미사용 예산은 팀 지갑으로 정확히 한 번 반환한다. `funded = remaining + returned + 지급 보상`을 추적한다.
- 이용권 교환은 소유자의 보상 잔액을 잠그고 처리한다. `(device_id,request_id)`로 재시도에 대한 이중 차감을 막고 서버의 상품 가격만 사용한다.
- 사용 시연은 내 이용권에만 가능하며 재시도해도 이미 사용된 상태를 유지한다. 매장 직원의 검증·실제 쿠폰은 구현하지 않는다.
- 기기 쿠키 기반 시연이다. 여러 기기 사용자를 동일인으로 인증하거나 다중 기기 부정 참여를 방지하지 않는다. 실결제·보상 운영에는 계정/팀 권한, 사용자 검증, 실제 결제/정산과 제휴가 별도로 필요하다.

## 결과와 예시

팀은 자기 카드의 스와이프 분포와 이유를 확인한다. 다른 기기는 자기 반응만 볼 수 있고, 전체 결과는 종료 후 리포트를 공개한 뒤에 표시한다. 5개 미만 반응은 비율을 숨긴다. 관심은 실제 구매 의향을 뜻하지 않으며 보상에 따른 응답 편향을 표시한다.

빈 발견 화면의 '시연 아이디어 준비'는 명시적 요청으로 가상 카드 3개와 카드별 3,000C 예산을 한 번 준비한다. 실제 주민 응답은 만들지 않고 반복 클릭으로 참여 이력/소진 예산을 초기화하지 않는다. 기존 예시와 실적을 주민 성과로 인용하지 않는다.

가상의 커피 40C, 한 끼 70C, 빵 세트 100C는 모두 시연용이다. 실제 매장명·로고·제휴·원화 가치는 없다.

## 실행

Docker의 `.env` 또는 Spring 실행 환경에 `DEMO_CREDITS=true`를 명시한다. Compose는 해당 변수를 백엔드로 전달한다. Next는 기존 `SPRING_API_URL`로 서버 API를 호출한다. 추가 결제 키나 브라우저 API 접근은 필요 없다. Flyway V8~V10은 새 테이블과 반환·팀 지갑을 추가하며 기존 아이디어·반응·결론을 지우지 않는다.

로컬 Tailscale 미리보기는 실행 중인 Mac, Spring, 전용 Postgres에 의존한다. 공개 배포·실제 주민·실제 상점 검증은 완료되지 않았다.

## 검증 기록

- 프론트 테스트 22개, 타입 검사·린트·운영 빌드 통과.
- 백엔드 112개 통과(크레딧 관련 18개 포함): 보상 동등성, 이유 가산, 중복, 동시 지급/예산 소진, 소유권, 부족 잔액, 마감 반환, 공개 전 결과 제한, 이용권 재시도, 충전/보상 분리, 비활성 모드.
- 실제 Tailscale 화면의 별도 시연 기기: 오른쪽 버튼과 이유 작성 → 30C, 실제 왼쪽 드래그 → 10C, 커피 40C 교환 → 사용 시연 → 새로고침 후 유지.
- 별도 팀 기기: 500C 충전(보상 지갑 0C 유지) → 새 카드 등록 → 300C 배정 → 다른 기기의 이유 참여 30C → 팀에서 이유 확인 → 종료·270C 반환(팀 470C) → 리포트 공개 → 참여 기기에서 결과 확인 → 보류 결론을 참여 기기의 내 활동에서 확인. 새 카드에는 `[시연 점검]`을 붙였으며 실제 주민 실적이 아니다.
- 320/375/1440px에서 발견·팀·혜택·등록·내 활동·상세의 가로 넘침 없음, 넓은 화면에서도 480px 이내 동일 캔버스. 브라우저 오류 없음.

- 320×740 / 375×812 / 1440×1000에서 관심 버튼과 하단 메뉴의 겹침 없음. 실제 터치 오른쪽 스와이프, 키보드 왼쪽 선택·Escape 취소 확인.
