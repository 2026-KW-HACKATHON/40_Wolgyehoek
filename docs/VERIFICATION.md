# 통합 검증 기록

검증일: 2026-10-06. 조원의 Spring PR 위에 Next 연결, 장끼 UI 이식, 배포 구성을 추가한 상태를 대상으로 했다.

## 자동 검증

- Java 21 / PostgreSQL 17.6: Spring 테스트 **94개**, 실패·오류·건너뜀 0. `./gradlew test bootJar` 성공.
- 실제 HTTP 통합 테스트: 카드 생성, 검색·탭, 닉네임 변경, 반응, 운영자 마감, 공개 전 권한/기기 키 비노출, 리포트 공개, 5명 미만 비율 숨김, 결론·알림·모두 읽음, 이어받기 연결.
- Linux CI에서 발견한 읽음 시각의 나노초/DB 마이크로초 정밀도 차이를 수정했다. 컨테이너 확인은 시작 중 연결 재설정을 재시도한다.
- 가려진 알림 접근 및 가려진 이어받기 자식 회귀 테스트 포함. 테스트 DB 이름 검사로 개발/운영 DB 초기화를 막는다.
- 프론트 도메인 테스트 **19개**, 타입 검사, ESLint, webpack 운영 빌드 성공. 빈 가격 거부/명시적 무료 가격 0을 확인했다.
- `docker compose --env-file .env.example config --quiet` 성공.
- GitHub Verify 워크플로는 웹 검사, 백엔드 테스트, 실제 Compose 이미지 빌드 및 API/화면 부팅 확인을 실행한다. 각 실행의 원격 성공 여부는 PR Checks를 확인한다.

## 기존 Next DB 이관

기존 DDL로 만든 별도 PostgreSQL DB에 소문자 결론·의견·알림·신고 및 운영 기록을 넣었다. 명시적 baseline 6 후 V7을 실행했다. 기존 카드의 보류 상태, 사유, 조건부 의견과 재시작 알림이 API에서 유지됐다. 운영/주민 DB는 변경하지 않았다.

## 실제 브라우저

Aside에서 서로 다른 기기 쿠키의 제안자/주민을 나눠 다음 흐름을 수행했다.

1. 자유 문장 → 규칙 기반 초안 → 수정 → 카드 게시.
2. 주민 5,000원 반응, 조건부 의견 및 조건 저장. 제안자의 다른 반응도 별도로 저장.
3. 운영 코드 진입 → 즉시 종료. 주민에게 공개 전 리포트 비노출 확인.
4. 제안자 리포트 공개 → 사유 태그와 이유를 포함한 보류 결론.
5. 주민 결론 알림 확인 → 닉네임 변경 → 모두 읽음.
6. 주민이 변경점을 적어 이어받기 → 새 카드의 원본 연결 확인 → 기존 응답자의 재시작 알림 확인.
7. 검증 중 탭과 검색어를 함께 적용하여 결과 1건 확인.
8. 빈 가격/조건 누락 시 오류 표시와 입력 내용 보존 확인.

## 배포 범위

Spring 운영 JAR와 Next standalone을 로컬에서 함께 실행해 검증했다. 신규 서버를 위한 Docker/Compose, CI, 환경변수와 기존 데이터 이전 절차를 준비했다. 공개 서버·도메인과 접속 정보는 아직 제공되지 않았으므로 공개 배포 완료를 주장하지 않는다. AI 외부 서비스 호출은 키 없이 규칙 기반 경로로 확인했다.
