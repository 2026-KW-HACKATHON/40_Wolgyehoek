# 동네서랍 기획·컨셉 (2026-10-08)

딥인터뷰(3라운드)로 정한 방향이다. **[결정]**은 사용자가 고른 것, **[제안]**은 이 문서의 제안값으로 확정이 아니다.

## 한 줄

- **문제:** 지역 문제를 푸는 시도는 매년 새로 시작되지만, 결과와 멈춘 이유는 남지 않아 같은 이유로 또 멈춘다.
- **해결:** 동네서랍은 시도가 끝날 때 결과와 멈춘 이유를 남기게 하고, 다음 팀이 시작할 때 그것을 먼저 보여준다.

청년 팀은 무료로 쓰고, 매년 과제·사업에 예산을 쓰는 대학·지자체·창업지원기관이 구독한다 [결정].

English: *The open memory of local problem-solving.*

## 기조

1. 지역 문제는 어디에나 있다. 가장 작은 개념(대상·장소·니즈·장벽)이 조합되어, 지역 특성에 따라 조금씩 다른 문제로 나타난다.
2. 그래서 문제에는 공통 성질이 있고, 해결까지의 접근·분석·해법은 다른 지역의 것을 참고할 수 있다.
3. 청년은 이미 대학 수업·지자체 사업·동아리·창업으로 많은 시도를 한다.
4. 막히는 곳은 문제를 정의하고 조사하는 단계다. 중복된 아이디어로 같은 실패를 반복하고, 의견이 모이지 않고, 관련 정보를 찾기 어렵다. 청년의 생산력이 그만큼 새어 나간다.
5. 동네서랍은 이 단계에 쓸 수 있는 아이디어 온톨로지를 제공해, 시도가 더 효율적으로 실현되게 한다.

## 대표 문제 [결정]

**결과와 멈춘 이유가 남지 않아, 같은 이유로 또 멈춘다.** 같은 아이디어를 다시 하는 것 자체는 문제가 아니다.

- 월계 지역 공개 기록 36건 중 멈춘 이유가 남은 기록은 0건이다. 시도는 남아도 왜 멈췄는지는 남지 않는다.
- 앱에 "홀몸 어르신 안부 확인"을 쓰면 이미 6번 나온 아이디어로 잡힌다(2020 학생 프로젝트 결과 미확인, 2024 구청 사업 4건 시행).
- 광운대 지역밀착형 캡스톤은 2015년부터 매년 노원구 현안을 다룬다. 학기가 끝난 뒤 무엇이 이어졌는지는 공개 기록으로 찾기 어렵다.

정보를 찾기 어려움과 의견이 모이지 않음은 같은 원인에서 나오는 하위 문제로 다룬다.

## 온톨로지

문제와 시도를 둘 다 1급 객체로 둔다 [결정]. 문제에서 들어가도, 시도에서 들어가도 서로 이어진다.

| 객체 | 뜻 |
|---|---|
| 개념 | 가장 작은 단위. 대상·장소·니즈·장벽·주체·출처. 니즈는 SDG 세부목표에 연결한다 [제안] |
| 문제 | 개념의 조합 + 지역 특성. 장소만 다르고 성질이 같은 문제는 묶인다 |
| 시도 | 문제를 풀려던 아이디어·과제·사업·정책. 결과(진행·보류·중단·미확인)와 이유를 가진다 |
| 의견 | 문제·시도에 붙는 공감·근거·반론·멈춘 이유 제보 [결정]. 의견이 온톨로지를 채운다 |

| 관계 | 뜻 |
|---|---|
| 다룸 | 시도 → 문제 |
| 막힘 | 시도 → 장벽(멈춘 이유) |
| 이어받기 | 멈춘 시도를 같은 곳에서 다시 |
| 재생산 | 된 해법을 다른 지역으로 옮김 |
| 참조 | 다른 시도를 근거로 인용 |
| 근거 | 시도·의견 → 출처 문서 |

결과를 모르는 기록은 실패로 세지 않는다. 개인 이름은 노드로 만들지 않는다.

## 공개 범위 [결정]

- **공개 커먼즈:** 문제·시도·결과·출처·의견. 누구나 보고, API와 MCP로 읽는다.
- **팀 워크스페이스:** 작업 중인 초안, 조사 노트, 팀 메모리. 비공개.

## 에이전트 등록

mori-contentcare의 등록 도우미 구조를 가져온다. 무엇을 물을지는 규칙이 정하고, 모델은 추출과 제안만 한다. 같은 입력에 같은 질문이 나오고, 모델이 실패해도 등록은 막히지 않는다.

- **입력 한 칸 [결정]:** 자유 서술, 기사·회의록 URL, 팀 기획서 파일, AI 앱(MCP).
- **근거는 싼 것부터:** 장소·개념 사전(규칙) → 동네서랍 그래프 → 페이지·문서 본문 → 모델.
- **에이전트가 하는 일 [결정]:**
  1. 개념 분해: 대상·장소·니즈·장벽으로 나눠 문제에 연결한다.
  2. 중복·선례 알림: 같은 문제의 지난 시도와 멈춘 이유를 보여주고 이어받기를 제안한다.
  3. 다른 지역 해법 추천: 같은 성질의 문제를 다른 지역이 어떻게 풀었는지 보여준다.
  4. 빠진 조사 질문: 대상 규모·기존 제도·운영 주체 같은 빈칸을 묻는다. 최대 3개, 답은 기본값을 미리 골라 둔다 [제안].
- **팀 메모리:** 소속·지역·분야를 기억해 다음 등록에서 묻지 않는다.
- **출처:** URL·파일 입력은 출처로 자동 기록한다. 사실과 가설을 나눠 저장한다.

## MCP 커넥터 [결정]

Claude·ChatGPT에서 커넥터로 쓴다. 대시보드와 같은 서비스를 쓰고, 커넥터는 도구로 감싸기만 한다.

| 도구 [제안] | 하는 일 |
|---|---|
| `search_problems` | 장소·대상·니즈로 문제 찾기 |
| `get_problem` | 문제 상세와 시도 계보 |
| `find_similar_attempts` | 아이디어 한 줄로 선례·다른 지역 해법 찾기 |
| `start_idea_intake` · `answer_idea_intake` · `register_idea` | 에이전트 등록 |
| `get_region_report` | 지역 리포트 |

읽기는 공개 커먼즈라 인증이 없어도 되고, 등록은 팀 계정 인증(OAuth)을 거친다.

## 지자체·정치 활용 [결정: 문제 분석 리포트]

지역 단위 리포트를 읽기 전용으로 제공한다.

- 이 지역에서 반복되는 문제와 시도 횟수
- 멈춘 이유 분포(운영 주체 없음, 예산·공간 부족 등)
- 아무도 손대지 않은 빈칸
- 지금 진행 중인 청년 시도
- 같은 문제를 다른 지역이 푼 방법

정책 시도를 직접 등록하고 결과를 남기는 기능은 다음 단계로 둔다 [제안].

## 데이터 [결정: 해외 사례까지]

- **지금:** 월계 지역 공개 기록 36건, 출처 10개. 36건 중 14건이 2024년 회의록 한 건에서 나왔다.
- **해커톤까지:** 데모 문제(홀몸 어르신 안부·고립)를 중심으로 국내 다른 지역 기록과 해외 공개 사례를 출처와 함께 추가한다. 국내 10~20건, 해외 5~10건 [제안].
- **기준:** 원문을 직접 조회해 대조한다. 예고·수상을 시행으로 바꾸지 않고, 멈춘 이유를 추정해 넣지 않는다.
- **표준:** 니즈는 SDG 세부목표, 장소는 행정구역 코드에 연결해 나라가 달라도 묶이게 한다 [제안].

## 해커톤 데모 시나리오 [제안]

주인공: 광운대 공학설계입문 팀.

1. 데스크탑에서 "월계1동 홀몸 어르신 안부를 매일 확인하는 서비스" 한 줄을 입력한다.
2. 에이전트가 개념을 나눈다: 대상 홀몸 어르신 · 장소 월계1동 · 니즈 안부·고립.
3. 선례: 이미 6번 시도됐다. 2020 학생 프로젝트는 결과 미확인, 구청 AI 자동전화는 시행 중이다.
4. 다른 지역·해외 해법을 함께 보여준다.
5. 빠진 조사 질문 3개에 답하고, 이어받기 또는 차별점으로 등록한다.
6. 문제 상세에 주민·현장 의견이 붙는다.
7. 같은 문제를 노원구 리포트 화면에서 지자체 시점으로 본다.
8. Claude에서 커넥터로 "월계동 어르신 고립 관련 시도 찾아줘"를 묻는다.

## 성공 지표 [제안]

- 등록할 때 선례를 확인한 비율
- 이어받기·재생산·참조 수
- 시도의 멈춘 이유 기록률
- 중복 없이 시작된 시도 비율
- 리포트를 열람한 기관 수

## 열린 결정

- 구현 순서와 발표 일정. [제안] 데이터 모델(문제·시도 분리, 관계 추가) → 데스크탑 탐색·상세 → 에이전트 등록 → 지역 리포트 → MCP → 해외 데이터.
- 모델 제공자와 비용 상한.
- 해외 사례 선정 기준.
- 리포트 형식(화면만 또는 내보내기).
- 의견의 신원 확인과 남용 방지.
- 글로벌 이름(해커톤은 동네서랍 유지 [결정]).
