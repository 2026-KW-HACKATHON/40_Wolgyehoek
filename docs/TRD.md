# 동네서랍 기술 명세

## 구성

Next.js 16 App Router / React 19가 화면과 Server Actions를 담당한다. Java 21 / Spring Boot 4가 데이터와 업무 규칙의 유일한 실행 주체다. PostgreSQL 17에 저장하며 Flyway V1–V7로 스키마를 관리한다. Next의 기존 내장 데이터베이스 및 중복 업무 로직은 제거했다.

브라우저 → Next Server Action/서버 렌더링 → Spring API → PostgreSQL 순서로 동작한다. `SPRING_API_URL`은 서버 전용이다. Next 프록시가 `dn_device` 쿠키를 발급하고 `lib/api.ts`가 Spring으로 전달한다. 클라이언트에는 다른 참여자의 기기 식별자를 보내지 않는다. 쿠키 기반 익명 참여이므로 다른 브라우저/기기로 바꾸면 참여 이력이 연결되지 않는다.

## 화면과 읽기 모델

- `/`: 검색과 전체/검증 중/기록 탭. Spring `GET /api/views/cards` 사용.
- `/new`: 자유 문장 초안 정리, 유사 아이디어 확인, 카드 게시.
- `/cards/{id}`: 반응, 의견, 공개 리포트, 결론과 이어받기 관계. `GET /api/views/cards/{id}`가 본인 반응·관리 권한을 포함한다.
- `/cards/{id}/takeover`: 이전 카드를 보존하고 새로운 카드로 이어받는다.
- `/me`: 본인이 제안/반응한 카드, 닉네임 수정, 알림과 읽음 처리. `GET /api/views/me` 사용.
- `/admin`: 운영자 코드 진입, 신고 처리, 카드 가리기.

장끼의 실제 공용 컴포넌트와 디자인 토큰을 가져온 화면 체계는 [UI-PORT.md](UI-PORT.md)를 따른다.

## 데이터와 핵심 규칙

카드, 기기, 반응, 의견, 결론, 알림, 신고, 운영 기록을 PostgreSQL에 저장한다. 반응은 카드·기기당 하나이며 변경할 수 있다. 4단계 수요 강도와 거주/직장·학교/방문 구분을 저장한다. 가격은 명시적으로 입력한 0–1,000,000원의 정수만 허용한다.

카드 상태는 검증 중, 결론 대기, 정체, 실행, 보류, 중단으로 계산한다. 마감 전 반응을 허용하고, 마감 후 제안자/운영자가 리포트 공개 및 결론을 기록한다. 비공개 리포트는 권한을 검사한다. 응답이 5명 미만이면 비율을 표시하지 않는다. 보류·중단에는 사유 태그와 이유가 필요하다. 조건부 찬성에는 조건이 필요하다.

결론을 기록하면 기존 응답자에게 알림을 생성한다. 보류·중단·정체 카드만 이어받을 수 있고 활성 자식 카드는 하나만 허용한다. 가려진 자식은 새 이어받기를 막지 않는다. 반응·결론·이어받기는 카드 행 잠금으로 직렬화한다. 기기는 충돌 안전한 삽입으로 생성한다. 가려진 카드의 조회 및 알림 접근은 차단한다.

## 운영 및 검증

`GET /api/health`는 데이터베이스 연결까지 확인한다. Spring OpenAPI는 `/swagger-ui/index.html`에서 확인한다. 운영자 코드는 서버 환경 변수로만 설정한다. 초안 생성은 Anthropic 키가 없거나 요청에 실패하면 규칙 기반 정리로 돌아간다. 실제 응답을 가장한 데모 데이터는 만들지 않는다.

신규 설치와 기존 Next PostgreSQL 이전은 [DEPLOYMENT.md](DEPLOYMENT.md)를 따른다. 기존 데이터는 자동 초기화하지 않는다. 테스트 DB의 이름이 `dongnae_test`일 때만 초기화를 허용한다. CI와 검증 결과는 [VERIFICATION.md](VERIFICATION.md)를 따른다.
